# Next milestone: reusable dispatch with stable lexical frames

Hypothesis: a per-execution mutable dispatcher plus value continuations can remove per-callee ExecutableFrameInterpreter construction/caller-object chains while retaining direct local and operand arrays. Current source/CPU gate B107 identifies the path; it does not predict speedup. The earlier B69 arena changed every hot load to use window offsets and additional activation indirection, and measured slower. This design must retain hot direct fields and existing arrays; B61's extra control holder must not survive alongside a new one.

First stage (bounded source/layout and semantic prototype): quantify current complete nonsimple helper allocations/control fields. Model one dispatcher, an existing stable ExecutableFrameState view for lexical users and a major-capacity-admitted value continuation stack. Save/restore actual current fields at call boundaries, not per-opcode frame/offset lookups. Preserve separate ExecutionContext identity and the existing native simple-return shortcut. Generators retain their own same-engine instance/suspended state. Do not introduce another execution backend, mode, policy or shared locals arena.

Expected deletion if accepted: ordinary child interpreter allocation in BeginPendingCall/CreateExecutableInterpreter, _caller object-chain ownership and duplicate normal-call execution/control lifetime paths. One value continuation contains the actual state needed to resume; no passive record wrapped around the old interpreter. Retain the existing general binder for dynamic calls and lowered evaluator obligations. Any stable frame-view allocation must be counted against removed storage, not hidden in the claim.

Semantic proof before timing: caller/closure/nonlocal/super/annotation/class/comprehension scopes, locals/vars snapshots and stable captured cells; defaults/rebinding/evaluation order; current exception/context/source spans across return/break/with/finally; nested generators/send/throw/delegation; real pending host/protocol operations; managed stack/recursion; first refusal even suppressed/finally returns; caller input/operand funding until child and awaited cleanup finish. Growing/replacing continuation backing must preflight retained capacity+overlap before mutating dispatch state; rollback must leave caller valid. Keep B99 fast native returns and all measured function optimizations.

Affected complete text-helper/search scripts, CSV/JSON native-helper controls and one captured/generator/protocol script. Use existing focused checks and two short independent before/after blocks with CPU/allocation/elapsed, complete goldens and budgets. No fixed percentage veto. Temporary regressions may be accepted during the isolated migration only with a named repayment/completion decision. Finish with one production call driver and removal of the displaced chain; if the construction claim collapses or control cost dominates, remove the whole prototype and retain evidence/independent regressions. Do not permanently close the architectural question because one observation times out or controls drift.

Stopping criteria: complete a source/layout proof and first semantic prototype within one bounded development stage; then decide whether the measured/control evidence justifies completion/refinement or a different dominant-work hypothesis. No open ownership audit, broad compiler rewrite, tagged-value campaign or final producer dependency.


Implementation proof obligations B108: publish immutable lexical storage views from frame entry, never the reusable mutable dispatcher. Retain direct dispatcher fields by copying only at call boundaries. Save every current control/generator/pending-call field; ordinary calls remove child interpreter construction and the caller object chain. Root/generator dispatchers remain the same engine. Source-span lookup for operand growth must follow the active frame, preserving a suspended span when appropriate. One coarse temporary reservation funds the value-continuation backing and full replacement overlap, with unused capacity retained until dispatcher/generator cleanup. No new owner or pool. Count the per-activation stable view and continuation copying against the removed interpreter storage. The existing frame array reservation funds the view metadata before allocation. Keep native simple-return shortcuts before any continuation construction. A first semantic prototype is not a retained optimization.
